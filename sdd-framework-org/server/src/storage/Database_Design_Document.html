2. Database Overview

The ShelfGuard AI database schema is architected to support high-frequency asynchronous computer vision processing pipelines, real-time inventory synchronization, optimistic-locked human-in-the-loop task approvals, and immutable audit logging. Point-in-time financial snapshots are embedded directly within event records to prevent historical pricing drift during stockout revenue recovery calculations.

3. Entity Definitions

  • products: Master catalog of retail SKUs, categories, pricing, and assigned shelf zones.
  • inventory: Real-time tracking of on-shelf quantities, backroom stock, POS velocity, and reorder thresholds.
  • planogram: Expected facings, minimum facing bounds, and promotional flags per zone and SKU.
  • shelf_events: Log of computer vision anomaly detections with optimistic locking versioning and immutable point-in-time pricing snapshots.
  • audit_logs: Append-only security and operational trail tracking all administrative and human approval actions.
  • traceability_matrix: Links functional requirements (REQ-001 through REQ-008) to user stories, ADRs, source code paths, and test artifacts.

6. Constraints & Validation

  • Non-Negative Quantities: Inventory quantities (`on_shelf_qty`, `backroom_qty`, `pos_last_hour_sales`, `reorder_threshold`) must be $\ge 0$.
  • Confidence Bounds: CV confidence scores must fall between `0.0` and `1.0`.
  • Optimistic Locking: Approvals require strict version matching (`WHERE event_id = :id AND version = :v`) to prevent race conditions.

7. Index Strategy

Optimized B-tree path indexes are established for high-frequency queries:

  • idx_shelf_events_status_created: Accelerates pending task queue retrieval for store managers.
  • idx_inventory_reorder: Optimizes stock differential and reorder evaluation loops.
  • idx_audit_logs_timestamp: Ensures rapid append-only forensic log searches.

14. Security & Auditing

Database security enforces AES-256 storage encryption at rest and TLS 1.3 in transit. All state-mutating actions (approvals, rejections, overrides) require explicit actor identification and write immutable delta snapshots to the audit_logs table.
