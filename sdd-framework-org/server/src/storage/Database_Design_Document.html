Visitor Management System: Database Design

1. PURPOSE

This document defines the schema architecture for the VMS, ensuring ACID compliance, security through RLS, and data integrity for visitor workflows.

2. DATABASE OVERVIEW

Utilizes PostgreSQL to enforce strict relationships between Users, Employees, and Visit logs. Design focuses on auditability and PII protection.

4. TABLE SPECIFICATIONS

TablePrimary KeyDescription
Usersuser_idAuthentication and RBAC metadata.
Employeesemp_idOrganization internal staff registry.
VisitHistoryvisit_idPrimary transactional log for visitor movements.

14. SECURITY

Row-Level Security (RLS) is implemented on the VisitHistory table to prevent unauthorized cross-departmental access. PostgreSQL SET LOCAL app.current_user_id is required for context-aware queries.

15. DATA RETENTION

PII is scrubbed via cron jobs after 30 days. Media assets are purged from S3 via Lifecycle Policies at 14 days.

16. PERFORMANCE

Partial unique indices are used on the visitor history to optimize the check-in validation lookup for high-traffic reception points.
