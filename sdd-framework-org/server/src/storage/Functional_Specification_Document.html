Functional Specification Document (FSD) v2.0

ShelfGuard AI — Retail Computer Vision Copilot & SDLC Traceability Engine

Enterprise-grade functional and technical specifications for autonomous retail store execution, inventory reconciliation, and transparent AI governance.

1. Executive Summary & Core Objectives

1.1 Executive Summary

ShelfGuard AI addresses the critical operational friction point in grocery and supermarket retail: the disconnect between backroom inventory and front-of-store shelf availability. By analyzing store-level shelf captures via asynchronous multimodal computer vision and optical character recognition (OCR), ShelfGuard AI automatically identifies out-of-stock gaps, low-stock conditions, planogram misalignments, and price-label mismatches.

Coupled with backroom inventory databases and synthetic planograms, it generates prioritized replenishment and corrective action tasks through non-blocking execution pipelines. Furthermore, it acts as a demonstration vehicle for modern AI-augmented engineering patterns—showcasing automated specification-driven development via Spec Kit, multi-agent orchestration via LangGraph, autonomous coding actions via Claude Code, and visual governance auditing via Google Antigravity.

Operational Efficiency

Reduce manual store-walk times by 70% and eliminate out-of-stock revenue leakage via non-blocking asynchronous ingestion.

Visual Intelligence Precision

Accurate bounding-box identification of empty facings, low-stock zones, and OCR price-tag auditing backed by graceful degradation fallbacks.

Human-in-the-Loop Integrity

Mandatory store manager approval before database writes, protected by optimistic locking concurrency controls and immutable audit logging.

Traceability Guarantee

Unbroken end-to-end Requirements Traceability Matrix (RTM) linking business requirements to ADRs, source code, unit tests, and runtime evidence.

2. User Personas and System Actors

Store Associate (Primary User)

Responsible for physical store tasks, restocking aisles, and processing daily deliveries. Interacts with ShelfGuard AI to capture/upload shelf images via asynchronous submission, review automated shelf-gap insights, and submit replenishment tasks for approval.

Store Manager (Secondary User)

Responsible for overall store performance, planogram compliance, and exception management. Reviews high-priority inventory alerts protected by optimistic concurrency controls, audits price-label mismatches, and grants final sign-off on automated restocking operations.

Retail Operations / Merchandising Head (Business Stakeholder)

Monitors regional category performance, stockout frequency trends, and financial recovery metrics via the executive impact dashboard utilizing point-in-time pricing snapshots.

Retail IT / AI Governance Team (Technical Stakeholder)

Monitors model confidence scores, false-positive feedback loops, privacy masking execution, and system-wide traceability logs through dedicated append-only audit trails.

3. End-to-End Operational Workflow

  1. Asynchronous Image Ingestion (REQ-001): Store Associate uploads a shelf bay photograph. The gateway immediately streams the payload locally, returns a 202 Accepted status with a polling token, and delegates heavy CV processing to background worker threads.
  2. Computer Vision Processing (REQ-002): The CV engine parses the image within a strict 2,500ms timeout window, generating bounding boxes and extracting OCR text. If inference fails or confidence drops below threshold ($\text{confidence} < 0.70$), synthetic fallback data is loaded gracefully.
  3. Data Enrichment & Planogram Cross-Reference (REQ-003): Queries indexed relational tables (products.csv, inventory.csv, planogram.csv) to map detected SKUs against expected facings and check backroom quantities.
  4. Recommendation Synthesis (REQ-004): Evaluates stock thresholds and computes a priority score, yielding a prioritized action item captured with point-in-time financial snapshots.
  5. Human Gate & Optimistic Approval (REQ-005): The recommendation remains PENDING until reviewed. Approvals enforce conditional optimistic locking (version checks) to eliminate race conditions, writing an immutable entry to the append-only audit log.
  6. Dashboard & Traceability Review (REQ-006 to REQ-008): Store managers view aggregated issue metrics via point-in-time valuation, while technical stakeholders inspect the live Requirements Traceability Matrix linking features to tests, code, and ADRs.

4. Functional Requirements & Logic Gates

REQ-001 Asynchronous Shelf Image Upload & Ingestion
  • Inputs: Multipart form-data containing image (image/jpeg, image/png, max 10MB), zone_id, associate_id.
  • Validation Rules: File extension must be `.jpg`, `.jpeg`, or `.png`; dimensions $\ge 800 \times 600$; `zone_id` must exist in active planogram schema.
  • Logic Gates: If size > 10MB, return 413 Payload Too Large. If invalid zone, return 400 Bad Request. Stream binary payload and return 202 Accepted with image_id and status QUEUED.
REQ-002 Shelf Gap & Anomaly Detection with Graceful Degradation
  • Inputs: image_id, binary image stream.
  • Validation Rules: CV model must execute within a strict 2,500ms timeout window.
  • Logic Gates: If live inference times out or confidence falls below threshold ($\text{confidence} < 0.70$), automatically trigger fallback mechanism loading pre-seeded synthetic anomaly records from shelf_events.csv. Detect structural coordinates $[x_1, y_1, x_2, y_2]$.
REQ-003 Planogram & Inventory Cross-Reference
  • Inputs: Detected SKU list, bounding box metadata, zone ID.
  • Validation Rules: Query indexed relational tables utilizing optimized B-tree path indexes for zone_id and sku_id.
  • Logic Gates: Match detected SKU against planogram expected facings; query inventory.csv for on_shelf_qty and backroom_qty. Output enriched event object with stock differentials.
REQ-004 Prioritized Recommendation Generation with Point-in-Time Snapshots
  • Inputs: Enriched inventory, anomaly data, and current product master records.
  • Logic Gates: If on_shelf_qty == 0 AND backroom_qty > 0 $\rightarrow$ Priority: HIGH, Recommendation: "Refill from backroom".
    If on_shelf_qty < reorder_threshold $\rightarrow$ Priority: MEDIUM, Recommendation: "Replenish before evening rush". Capture unit price and product name as immutable point-in-time snapshots.
REQ-005 Optimistic-Locked Human-in-the-Loop Approval Gate
  • Inputs: event_id, authorization token, decision (APPROVE | REJECT), record version number (version).
  • Validation Rules: User must possess STORE_ASSOCIATE or STORE_MANAGER role.
  • Logic Gates: State transition requires conditional match: WHERE event_id = :id AND version = :v AND human_status = 'PENDING'. If version mismatch occurs, return 409 Conflict. Increment version and write immutable audit log.
REQ-006 — REQ-008 Dashboard, Traceability, & Automated Artifact Generation
  • Dashboard (REQ-006): Real-time valuation metrics computed using captured point-in-time financial snapshots ($\text{unit price} \times \text{missing facings}$) to prevent historical price drift.
  • Traceability Matrix (REQ-007): Maps 1-to-N relationships between requirement IDs, user stories, ADR identifiers, source files, and test suite execution functions.
  • Artifact Generation (REQ-008): Compiles Spec Kit markdown, ADR documents, test execution reports, and governance checklists into static build bundles.

6. Data Model Constraints & Schema Design

The system relies on SQLite / PostgreSQL relational schemas incorporating check constraints, foreign key referential integrity, and high-frequency B-tree indexes optimized for sub-millisecond status queries and append-only auditing.

products Stores primary SKU metadata, expected zones, unit prices, and category priorities.
inventory Tracks real-time on-shelf qty, backroom qty, POS sales velocity, and reorder thresholds.
planogram Defines structural zone specifications, expected facings, min facings, and promo flags.
shelf_events Logs detected anomalies, confidence scores, optimistic lock versions, and price snapshots.
audit_logs Immutable append-only table logging actor actions, state hashes, and payload snapshots.
traceability_matrix Binds requirement IDs to user stories, ADRs, source paths, test paths, and evidence.

7. Compliance & Security Mandates

Role-Based Access Control

Strict enforcement of privileges across STORE_ASSOCIATE, STORE_MANAGER, and ADMIN roles for uploads, overrides, and audit management.

Data Privacy & Masking

Facial anonymization preprocessing filters applied to all shelf captures. Zero production CCTV feeds or real customer PII persisted.

Encryption Standards

TLS 1.3 encryption in transit across all endpoints. AES-256 database storage encryption at rest with secrets isolated in environment variables.

Immutable Audit Logging

Every administrative override and human approval records timestamps, actor IDs, prior vs. new state hashes, and payload snapshots.
