1. Introduction

1.1 Purpose: To define the technical and functional requirements for the VMS to ensure secure, digitized visitor tracking.

1.2 Scope: Web-based reception logging, photo capture, employee notification, and visitor reporting.

1.3 Objectives: Error reduction, 100% audit compliance, and automated PII anonymization.

2. Business Context

Current Process: Manual paper registers, prone to illegibility and lack of real-time employee notification.

Future Process: Digitized registration with direct-to-S3 photo storage, RLS-enforced data isolation, and automated anonymization.

5. Functional Requirements

FR-001: Registration & Check-In

Description: Capture visitor data and store photo via S3.

Logic: BR-001 (Unique mobile check), BR-005 (Async notification).

Acceptance Criteria: Success message upon ID generation; Photo URL mapped to record.

Related API: POST /api/visitors/check-in

6. Business Rules

  • BR-001: Partial Unique Index on mobile for active visits (Enforcement: DB Trigger).
  • BR-002: Chronology constraint (check_out > check_in) (Enforcement: Table Constraint).
  • BR-005: Non-blocking async dispatch for notifications (Enforcement: Application Logic).

14. Non-Functional Requirements

  • Security: Double-token pattern (15m JWT expiry); RLS enabled on all queries.
  • Performance: API response time < 2s; S3 lifecycle policy purging at 14 days.
  • Privacy: Async anonymization of PII for records > 30 days old.
