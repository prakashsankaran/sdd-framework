ShelfGuard AI — Test Strategy & Test Cases Specification

Enterprise Computer Vision Copilot, SDLC Traceability, and Non-Blocking Ingestion Pipeline Test Architecture

1. Test Strategy Summary

1.1 Scope

The scope encompasses end-to-end functional verification, non-blocking asynchronous queuing behavior, computer vision timeout handling (2,500ms SLA), graceful degradation mechanisms, optimistic concurrency control (version locking), database DDL constraints, role-based access control (RBAC), transport encryption (TLS 1.3), data privacy masking, and the automated Requirements Traceability Matrix (RTM) engine.

1.2 Objectives

  • Validate that asynchronous payload ingestion correctly processes multipart uploads and returns immediate `202 Accepted` queue tokens.
  • Ensure strict adherence to computer vision processing constraints, including 2,500ms timeout boundaries and fallback synthetic event loading.
  • Verify absolute data integrity under race conditions using SQL optimistic locking (`WHERE version = :v`) during store manager approvals.
  • Guarantee robust security enforcement across RBAC roles, facial anonymization pre-processing, and append-only audit log immutability.

1.3 Entry Criteria

  • Approved functional specification (`spec_v2.md`) and database DDL schema.
  • Successful deployment of the test environment containers and initial seed datasets (`products.csv`, `inventory.csv`, `planogram.csv`, `shelf_events.csv`).
  • Passing static code analysis and schema validation reports.

1.4 Exit Criteria

  • 100% execution of P1 (Critical) and P2 (High) test cases with 0 unmitigated defects.
  • Automated test suite passing rate ≥ 98% across unit, integration, and security suites.
  • Complete mapping verification across all RTM nodes (`REQ-001` through `REQ-008`).

1.5 Test Approach & Levels

A multi-layered test pyramid approach is enforced:

  • Unit Testing: Isolated validation of detection algorithms, database schema constraints, and priority scoring functions.
  • Integration Testing: API endpoint verification, asynchronous worker queue dispatching, and relational cross-referencing against planograms and inventories.
  • System & End-to-End (E2E) Testing: Simulated store associate uploads through manager approval workflows and impact dashboard snapshot aggregations.
  • Non-Functional Testing: Security penetration checks, TLS 1.3 verification, concurrency race-condition testing, and CV timeout resiliency testing.

1.6 Defect Management & Risk Matrix

  • Defect Severity Levels: P1-Blocker (System crash, data corruption, security bypass), P2-Critical (Core feature failure without workaround, CV timeout violation), P3-Major (UI metric drift, minor validation discrepancy), P4-Minor (Cosmetic formatting).
  • Key Risks & Mitigations:
    • Risk: CV inference latency exceeding 2,500ms window during peak hours.
      Mitigation: Automated graceful degradation fallback testing injecting pre-seeded synthetic anomalies.
    • Risk: Race conditions during simultaneous store manager approvals.
      Mitigation: Rigorous concurrency testing targeting optimistic locking version increments and HTTP 409 responses.

3. High-Level Test Scenarios (Grouped by Module)

Module 1: Ingestion & Upload (REQ-001)

  • TS-ING-01: Valid multipart shelf image upload & queue initialization.
  • TS-ING-02: File size and dimension boundary validation checks.
  • TS-ING-03: Zone ID validation against active planograms.

Module 2: Computer Vision & Fallback (REQ-002)

  • TS-CV-01: Successful bounding box detection within 2,500ms SLA.
  • TS-CV-02: Graceful degradation fallback on inference timeout (>2,500ms).
  • TS-CV-03: Low confidence threshold fallback (<0.70 confidence).

Module 3: Cross-Reference & Scoring (REQ-003, REQ-004)

  • TS-REF-01: Planogram facing and backroom inventory relational cross-matching.
  • TS-REF-02: Priority scoring algorithm verification (HIGH vs. MEDIUM).
  • TS-REF-03: Point-in-time financial snapshot capture.

Module 4: Approvals & Audit (REQ-005, REQ-006, REQ-007, REQ-008)

  • TS-GOV-01: Optimistic locking concurrency enforcement (HTTP 409 Conflict).
  • TS-GOV-02: Immutable audit logging on state transitions.
  • TS-GOV-03: RTM traceability chain verification.
