ShelfGuard AI

Enterprise Retail Computer Vision Copilot & SDLC Traceability Engine — Technical Specification & Architecture Design

1. Executive Summary & Goals

1.1 Executive Summary

ShelfGuard AI addresses a critical operational friction point in grocery and supermarket retail: the disconnect between backroom inventory and front-of-store shelf availability. By analyzing store-level shelf captures via asynchronous multimodal computer vision and optical character recognition (OCR), ShelfGuard AI automatically identifies out-of-stock gaps, low-stock conditions, planogram misalignments, and price-label mismatches.

Beyond its business capabilities, ShelfGuard AI serves as a demonstration vehicle for modern AI-augmented engineering patterns—showcasing automated specification-driven development via Spec Kit, multi-agent orchestration via LangGraph, autonomous coding actions via Claude Code, and visual governance auditing via Google Antigravity.

1.2 Core Objectives

  • Business Operational Efficiency: Reduce manual store-walk times by 70% and eliminate out-of-stock revenue leakage by instantly converting shelf images into validated replenishment work orders via non-blocking asynchronous ingestion.
  • Visual Intelligence Precision: Deliver accurate bounding-box identification of empty facings, low-stock zones, and OCR text extraction for price-tag auditing against master ERP catalogs, backed by graceful degradation fallback mechanisms.
  • Governance & Human-in-the-Loop Integrity: Ensure that all AI-generated inventory interventions require explicit store manager/associate approval before writing to core execution databases, protected by optimistic locking concurrency controls and immutable audit logging.
  • Traceability Guarantee: Implement an unbroken end-to-end Requirements Traceability Matrix (RTM) linking business requirements directly to underlying ADRs, source code files, unit tests, and runtime evidence.

2. User Persona, Actors, and User Flows

2.1 Actors & Personas

  • Store Associate (Primary User): Captures/uploads shelf images via asynchronous submission, reviews automated shelf-gap insights, and submits replenishment tasks for approval.
  • Store Manager (Secondary User): Reviews high-priority inventory alerts protected by optimistic concurrency controls, audits price-label mismatches, and grants final sign-off on automated restocking operations.
  • Retail Operations / Merchandising Head: Monitors regional category performance, stockout frequency trends, and financial recovery metrics via the executive impact dashboard utilizing point-in-time pricing snapshots.
  • Retail IT / AI Governance Team: Monitors model confidence scores, false-positive feedback loops, privacy masking execution, and system-wide traceability logs through dedicated append-only audit trails.

3. Functional Requirements List

Requirement ID Description & Core Logic Outputs / Gates
REQ-001 Asynchronous Shelf Image Upload & Ingestion. Multipart form-data validation (JPEG/PNG < 10MB, dimensions ≥ 800x600, valid zone_id). Returns 202 Accepted with unique image_id and QUEUED status.
REQ-002 Shelf Gap & Anomaly Detection with Graceful Degradation within strict 2,500ms timeout window. Triggers synthetic fallback if confidence < 0.70. Array of detected anomalies: EMPTY_FACING, LOW_STOCK, PRICE_LABEL_MISMATCH.
REQ-003 Planogram & Inventory Cross-Reference via B-tree indexes mapping expected facings and backroom quantities. Enriched event object with stock differentials and backroom availability status.
REQ-004 Prioritized Recommendation Generation with Point-in-Time financial snapshots (unit price, velocity). Structured recommendation record with priority level and financial valuation.
REQ-005 Optimistic-Locked Human-in-the-Loop Approval Gate enforcing conditional version checks to eliminate race conditions. Updated event record with incremented version and immutable audit log entry.
REQ-006 Issue & Impact Dashboard with Snapshot Valuation computing estimated sales recovery without historical drift. Dashboard JSON payload containing summary metrics, category distribution, and task queues.
REQ-007 Requirements Traceability Matrix (RTM) mapping 1-to-N relationships between requirements, stories, ADRs, and tests. Unified traceability graph and tabular mapping view.
REQ-008 Automated Artifact Generation compiling Spec Kit markdown, ADRs, and test execution reports. Generated build artifact bundle.

5. Data Model Constraints

Database DDL schema compatible with SQLite and PostgreSQL, featuring performance indexes and snapshot preservation columns:

-- Products Master Table
CREATE TABLE products (
    sku_id VARCHAR(32) PRIMARY KEY,
    product_name VARCHAR(128) NOT NULL,
    category VARCHAR(64) NOT NULL,
    expected_shelf_zone VARCHAR(64) NOT NULL,
    unit_price DECIMAL(10, 2) NOT NULL,
    priority VARCHAR(16) NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Inventory Real-Time Table
CREATE TABLE inventory (
    sku_id VARCHAR(32) PRIMARY KEY,
    on_shelf_qty INTEGER NOT NULL CHECK (on_shelf_qty >= 0),
    backroom_qty INTEGER NOT NULL CHECK (backroom_qty >= 0),
    pos_last_hour_sales INTEGER NOT NULL CHECK (pos_last_hour_sales >= 0),
    reorder_threshold INTEGER NOT NULL CHECK (reorder_threshold >= 0),
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (sku_id) REFERENCES products(sku_id)
);

-- Shelf Events & Audit Log Table with Optimistic Locking & Snapshots
CREATE TABLE shelf_events (
    event_id VARCHAR(64) PRIMARY KEY,
    image_id VARCHAR(64) NOT NULL,
    detected_issue VARCHAR(32) NOT NULL,
    sku_id VARCHAR(32),
    confidence DECIMAL(4, 3) CHECK (confidence BETWEEN 0.0 AND 1.0),
    recommended_action TEXT NOT NULL,
    human_status VARCHAR(16) NOT NULL DEFAULT 'PENDING',
    version INTEGER NOT NULL DEFAULT 1,
    captured_unit_price DECIMAL(10, 2) NOT NULL,
    captured_product_name VARCHAR(128) NOT NULL,
    approved_by VARCHAR(64),
    approved_at TIMESTAMP,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (sku_id) REFERENCES products(sku_id)
);

-- Dedicated Append-Only Audit Logs Table
CREATE TABLE audit_logs (
    audit_id SERIAL PRIMARY KEY,
    timestamp TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    actor_id VARCHAR(64) NOT NULL,
    actor_role VARCHAR(32) NOT NULL,
    action_category VARCHAR(64) NOT NULL,
    target_resource VARCHAR(64) NOT NULL,
    prior_state_hash VARCHAR(64) NOT NULL,
    new_state_hash VARCHAR(64) NOT NULL,
    payload_snapshot TEXT NOT NULL
);

-- High-Frequency Query Performance Indexes
CREATE INDEX idx_shelf_events_status_created ON shelf_events(human_status, created_at DESC);
CREATE INDEX idx_shelf_events_sku ON shelf_events(sku_id);
CREATE INDEX idx_audit_logs_timestamp ON audit_logs(timestamp DESC);

6. Compliance & Security Mandates

  • Role-Based Access Control (RBAC): Strict separation between STORE_ASSOCIATE (upload & preliminary review), STORE_MANAGER (optimistic approval & overrides), and ADMIN (governance & traceability auditing).
  • Data Privacy & Masking: Automated facial anonymization preprocessing on captured shelf images; raw unmasked images are prohibited from persistent retention. Synthetic data isolation for hackathon environments.
  • Transport & Storage Encryption: TLS 1.3 enforced for all transport channels; AES-256 storage encryption for database files. Secrets isolated in environment variables.
  • Audit Logging: Immutable logging of all administrative overrides, approvals, and anomaly flags containing UTC timestamps, actor IDs, roles, and state hash verification.

8. Architecture & Edge Case Handling

  • CV Latency & Timeouts: Handled via asynchronous worker queues and graceful degradation falling back to pre-seeded synthetic anomaly records ($ ext{confidence} < 0.70$).
  • OCR Price Parsing Anomalies: Strict regex boundary matching wrapped in try/catch blocks defaulting to PRICE_PARSE_ERROR.
  • Concurrency Race Conditions: Optimistic locking mechanisms enforce conditional state matches (WHERE version = :v AND human_status = 'PENDING'), throwing 409 Conflict on version mismatch.
  • Traceability Drift: Immutable Requirement IDs embedded as code annotations and test decorators verified automatically during pipeline runs.
