# Conflict Resolution Matrix

| Conflict Issue | Viewpoints / Debate Arguments | Resolution & Evidence-Based Reasoning |
| :--- | :--- | :--- |
| **1. Custom Billing Microservice vs. Managed Vendor Portal** | **Architect / DevOps**: Initially proposed building a decoupled microservice (or KEDA-scaled background workers) to support billing.<br>**PO / Devil's Advocate / Performance**: Recommended offloading billing to a managed merchant portal (e.g., Stripe/Braintree) to avoid building complex transactional engines and PCI compliance overhead. | **Resolved: Managed Portal as Primary Requirement; Custom Microservice as Secondary Alternative.**<br>Evidence from *Order Ingestion v1* and *Customer Claim Ingestion* demonstrates that custom transactional caching and media handling introduce high operational failure risks. Adopting a pre-built merchant customer portal eliminates PCI-DSS scope, state caching issues, and binary processing overhead natively. If custom billing is strictly required, it must be isolated to Phase 2 with strict event-driven invalidation. |
| **2. Causation Fallacy & Development Halt vs. Immediate UX Modernization** | **Devil's Advocate**: Argued that assuming load time causes the 25% retention drop is a fallacy; requested halting work until retention telemetry is gathered.<br>**PO / Architect**: Countered that delaying mobile/UX fixes while retention drops 25% presents an unacceptable business risk. | **Resolved: Proceed with UX Modernization with Mandated Retention Telemetry.**<br>Mobile optimization and load time improvements are table stakes. Work on Phase 1 UI modernization will proceed alongside strict Core Web Vitals targets, but the spec must mandate embedding product analytics/telemetry to track user drop-off points and validate retention causality. |
| **3. Infrastructure Complexity (KEDA/K8s vs. Edge/Serverless)** | **DevOps**: Proposed Kubernetes with KEDA queue depth autoscaling and Argo Rollouts.<br>**Performance / Devil's Advocate**: Warned against over-engineering infrastructure for a web portal, advocating for Serverless/Edge CDN deployment. | **Resolved: Hybrid Edge Delivery & Pragmatic Autoscaling.**<br>Deploy the responsive frontend to an Edge CDN / Serverless platform (or lightweight container setup) to address latency directly. Reserve message queue-based worker scaling (KEDA/SQS) exclusively for backend asynchronous job processing if custom billing workflows are mandated. |
